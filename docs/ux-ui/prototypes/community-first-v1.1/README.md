# TPS360 Wireframes v1.1

Status: APPROVED UX LOGIC
Approval date: 2026-07-25
Artifact type: low-fidelity UX prototype, not production frontend

## Purpose

This prototype records the approved community-first UX logic for the first six TPS360 screens before high-fidelity design and frontend implementation begin.

It is a versioned UX artifact under `docs/ux-ui/prototypes/community-first-v1.1/`. It must not be treated as application code, a production frontend, or a source of confirmed API behavior.

## Approved Screens

1. Community Catalog.
2. Community Profile / Passport.
3. Community Geospatial Overview.
4. Threat Selection / Threat Profile.
5. Scenario Selection for Community.
6. Simulation Context Snapshot.

## Community-First User Flow

Community Catalog -> Community Profile / Passport -> Community Geospatial Overview -> Threat Selection / Threat Profile -> Scenario Selection for Community -> Simulation Context Snapshot.

Lobby is included only as `PREVIEW — STAGE 2, NOT APPROVED WIREFRAME` to show the direction after session creation. It is not one of the six approved v1.1 wireframes.

## Markers

- `REAL DATA`: confirmed data only. Do not add this marker unless the source is verified.
- `MOCK DATA`: illustrative placeholder data used to validate UX logic. It must not be copied into product records as fact.
- `API REQUIRED — PROPOSED CONTRACT, NOT IMPLEMENTED`: proposed frontend need for a backend/API contract that is not implemented or not confirmed.
- `PRODUCT DECISION REQUIRED`: unresolved product rule or governance decision.

## Constraints

- This is a low-fidelity UX prototype.
- This is not the TPS360 production frontend.
- The prototype does not implement backend behavior.
- The prototype does not approve new roles, participant counts, rounds, timing, or game mechanics.
- Bereznehuvatska community appears only as test/example content.
- Unconfirmed mock data must never be used as factual community data.
- Missing APIs in the prototype are not implemented APIs.
