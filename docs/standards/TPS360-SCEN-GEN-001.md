# TPS360-SCEN-GEN-001 — Participant-aware генерація кризи

**Версія:** 0.1
**Статус:** підготовлено для продуктової погодженості
**Дата:** 2026-07-28
**Власник:** команда продукту TPS360

## 1. Мета

Криза формується **під наявних учасників**, а не навпаки. Мета — **нуль пасивних
ролей**: кожна присутня в сесії роль має осмислену дію. Приклад проблеми: 7
учасників, з них 2 директори шкіл; «пожежа в полі» не дає їм дій — недопустимо.

## 2. Джерела та межі

Узгоджено з `MASTER_PROJECT.md`, `SKILL.md`, `ADR-0015` (командна модель),
`TPS360-ROLE-UX-001` (каталог ролей), `TPS360-SIM-001` (сценарій, життєвий цикл),
`TPS360-RES-001` (ресурси). Не змінює backend API — потрібні окремі контракти.

## 3. Принцип

Вхід генерації = **паспорт громади + присутні ролі (ростер сесії) + навчальні цілі**.
Сумісність сценарію тепер має два виміри:
1. **Географія/громада** (наявний `ScenarioCompatibilityEvaluator` — рельєф, близькість АЕС тощо);
2. **Покриття ролей** — чи має кожна присутня роль дію.

## 4. Алгоритм

```
1. Ростер сесії → карта релевантності: який об'єкт/завдання чіпає кожну роль.
2. AI підбирає/тюнить кризу (HazardType + геометрія) так, щоб чіпати об'єкти присутніх ролей.
3. Для ролей поза ядром кризи → додати ВТОРИННУ УМОВУ, що їх включає
   (напр. школа = пункт евакуації/укриття при пожежі поблизу).
4. Engagement guard: кожна активна роль має ≥1 рішення/директиву.
5. Фасилітатор схвалює/коригує AI-пропозицію (потік approve-ai-proposal, ADR-0015).
```

## 5. Політика покриття

- **Ціль покриття — 100%** присутніх ролей мають дію (нуль пасивних).
- Idle-роль **не** лишається спостерігачем: сценарій **дотягується** вторинною
  умовою, що дає їй завдання (не змінюючи ядро кризи).
- Вторинні умови мають бути реалістичні й прив'язані до паспорту громади.

## 6. Заборонені підміни

- Не залишати присутню роль без дії заради «чистоти» сценарію.
- Не вигадувати вторинні умови поза реальністю громади/паспорту.
- Не обходити схвалення фасилітатора.

## 7. Відкриті продуктові рішення

1. Формальна карта релевантності «роль → тип об'єкта/завдання».
2. Поріг покриття, якщо 100% недосяжно (резерв/ротація).
3. Пріоритет навчальних цілей vs реалізм при доборі вторинних умов.

## 8. Acceptance criteria

- Генерація приймає ростер ролей і повертає кризу з дією для кожної присутньої ролі.
- Idle-роль отримує вторинну умову, а не порожній екран.
- Фасилітатор бачить і затверджує пропозицію до старту.
