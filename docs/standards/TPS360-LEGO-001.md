# TPS360-LEGO-001 — Постачання LEGO-карток рішень

**Версія:** 0.1
**Статус:** підготовлено для продуктової погодженості
**Дата:** 2026-07-28
**Власник:** команда продукту TPS360

## 1. Мета

LEGO-картки (`LegoDecisionCard`: `action_type` + ціль + `allocated_resources`)
постачаються **контекстно й порційно**, а не як очевидний «правильний» вибір.
Заборонено інтуїтивне вгадування — правильна дія має вимагати читання контексту
громади/кризи та **комбінування**, не клік по картці з назвою рішення.

## 2. Джерела та межі

Узгоджено з `ADR-0015` (ролі/ієрархія), `TPS360-RES-001` (ресурси),
`TPS360-SCEN-GEN-001` (генерація кризи), `TPS360-SIM-001`. Гілки розвитку беруться
з наявних 5 проєкцій FacilitatorConsole (`CrisisLifecycleProjectionVariant`).

## 3. Модель постачання

```
1. Стартова рука: N карток на роль; тип/к-ть за роллю.
   Командир (Нач. Штабу / local-gov-head) = найширший набір варіантів;
   решта — вужче, за зоною відповідальності ролі.
2. Раунд → життєвий цикл кризи гілкується (вітер, дороги, ескалація) = активна проєкція.
3. Дрип: під активну гілку видати ПІДмножину карток причетним ролям
   (база ~10%, росте з тяжкістю гілки) — не всі, щоб вибір був нетривіальний.
4. Ескалація гілки (падіння mitigation% / зростання радіуса) → додати картки ЛІКВІДАЦІЇ
   (важче списання ресурсів).
5. Анти-вгадування: у видану підмножину домішувати правдоподібні-але-неоптимальні
   та часткові картки-дистрактори.
```

## 4. Параметри (тимчасові дефолти)

- Розмір стартової руки — за command tier (командир найширше); коефіцієнт уточнюється.
- Дрип база **10%**, масштабується з тяжкістю активної гілки.
- «Гілка гіршає» = падіння mitigation% або зростання радіуса ураження між раундами.

## 5. Заборонені підміни

- Не давати одну очевидно-правильну картку.
- Не видавати весь пул одразу.
- Не робити дистрактори абсурдними (мають бути правдоподібні).

## 6. Відкриті продуктові рішення

1. Формула розміру стартової руки за tier.
2. Крива масштабування дрипу від тяжкості.
3. Частка/логіка дистракторів у підмножині.
4. Точний критерій ескалації гілки.

## 7. Acceptance criteria

- Кожна роль отримує стартову руку відповідно до ролі; командир — найширшу.
- Нові картки з'являються лише під активну гілку, порційно (не весь пул).
- У наборі є неоптимальні/часткові опції; немає одноклікового «правильного» рішення.
- Ескалація гілки додає картки ліквідації.
